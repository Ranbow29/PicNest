## 2. 这一整天的战果（按主题）

### 2.1 一个自己挖的坑（最重要）

上一轮把缩略图从 webp 换成 jpg 时，把 DB 里 `thumbnail_path` **全置空**让它们按需重生。结果空窗期里**每个格子都在加载原图**：1182KB / 解码 26.6ms 一张，一屏 20 张 ≈ 500ms 纯解码。

| 格式 | 体积 | 解码 |
|---|---|---|
| 原图 | 1182 KB | 26.6 ms |
| 旧无损 webp | 185 KB | 1.9 ms |
| 现在 JPEG q80 | 35 KB | 0.9 ms |

修法：离线脚本把 10758 张 webp 重编码成 `{hash}-q80.jpg` 并回写 DB（14.6 秒），同时**拆掉 db.rs 里"把 webp 路径置空"那段破坏性代码**。

### 2.2 「不跟手」的真凶：宿主消息泵被烧

Feb 报「连续换 3–4 次文件夹就变慢」「点了没反应」。测量方法（**这套方法比任何 Chromium 指标都直接**）：

```python
user32.SendMessageTimeoutW(hwnd, WM_NULL, 0, 0, SMTO_ABORTIFHUNG, 3000, byref(out))
```

这是 Win32 标准心跳：宿主消息泵堵住它就不返回。再配 `GetThreadTimes(主线程)` 区分"在算"还是"在等"。

修前 / 修后：

| 指标 | 空闲 | 修前 | 修后 |
|---|---|---|---|
| 消息泵 WM_NULL 往返 | 0.1–0.3ms | 312 / 877 / 1891 / 3001ms | **0.2–0.4ms** |
| 真实鼠标点击 → 页面收到 | 4ms | 1320 / 1880 / 3334ms | **3–8ms** |
| 切后首条 IPC 命令 | 1–2ms | 583 / 1314 / 1600 / 3926ms | **2–3ms** |

**根因：`openDir()` 里的 `collectiveShake()`** —— 树上 60+ 图标同时重播动画，把宿主主线程烧到 70–80% CPU，消息泵堵 0.6–3 秒。已移除（卡片入场波保留）。

排除清单（别再走一遍）：图片加载量、入场波、AnimIcon 的 rAF 循环、后台任务、`AbortController.abort()`、诊断日志、IPC 大响应、**GPU flags**（`--disable-gpu-vsync` / `--disable-frame-rate-limit` / `gpu-rasterization` / `zero-copy` / `CanvasOopRasterization` / `UseSkiaRenderer` **全部已撤除**，A/B 证明不是原因）。

窗口最小化只能把阻塞从 1.4s 降到 0.3s —— **别被"窗口看不见就不卡"骗了**。

### 2.3 IPC 的教训

- 取数（`images_by_dir`）走**本地 HTTP**，不用 IPC：同一时刻 IPC 1.8s、HTTP 25ms。
- `rename_image` / `set_image_meta` / `images_reorder` / `apply_transform` / `mkdir` 已从主线程卸下（改 `async + spawn_blocking`）。**sync 命令确实在 `[main]` 线程**，已由 `CmdTimer` 的线程名实证。
- 窗口操作类（最小化/置顶）和 OLE 拖放（`drag_begin`/`copy_files_to_clipboard`）**必须留主线程**。
- 仍未改的 sync 命令：`move_*` / `rename_dir` / `physical_*`（已删）/ `strip_order_prefixes`（已删）/ `stage_drop_*`。

### 2.4 排序与文件名（改动最大的一块）

拆掉旧的「物理排序」三命令（`physical_order_images/dirs`、`strip_order_prefixes`）——它们会 `thumbnail_path = NULL`，一次全量排序清空整库缩略图。

新方案：**三层分离**

| 层 | 存哪 | 谁读 |
|---|---|---|
| 图片顺序 | `images.sort_order` | 图巢网格 |
| 目录顺序 | `picnest_dir_order` | 左栏树 |
| 文件名前缀 | 磁盘 `001_原名.jpg` | 资源管理器 |

前两层是主，第三层是投影。同步机制：

- **「排序同步文件名」开关**（右键，默认关，localStorage 记忆）：拖完 800ms 自动把**当前这一层**顺序写进文件名
- 只改编号与实际位置不符的（顺序没变时 `changed = 0`）
- 改名时**迁移缩略图缓存**（`old_hash → new_hash`），**绝不置 NULL**
- 两阶段改名用 `.picnest-tmp-*`，单项失败回滚
- **自动同步走本地增量**：用后端返回的 `map` 替换 `file_path`/`thumbnail_path`，不整表 `loadImages`，**选中/滚动/入场波都不打断**

**踩过的坑**：改名会产生大量文件事件，watcher 随即 `loadImages`，把刚写好的顺序盖回去（实测把顺序搞乱）。修法：内部操作期间设 `_suppressFsSyncUntil` 抑制 watcher 回写。

### 2.5 同步（两个方向，现在都是自动的）

| 方向 | 机制 |
|---|---|
| 磁盘 → 库 | 切进目录 1.2s 后扫一次 + **文件监听**（新增/删除/改名） |
| 库 → 磁盘 | 「排序同步文件名」开关（拖完 800ms） |

**文件监听**：`notify` crate → Windows `ReadDirectoryChangesW`，递归监听所有根，600ms 防抖（硬上限 2s），只看 Create/Remove/Rename。**内核事件通知，不轮询、不读文件内容。**

**删除同步是这轮补上的**（历史上从来没有）：

- 证据：`sync_folder_snapshot` / `sync_dir_snapshot` 的 diff 只遍历「磁盘上的文件」，只判断「磁盘有库没有」和「大小/mtime 变了」，**从未反向检查「库有磁盘没有」**
- 修法：watcher 收到 Remove → 立即软删；`sync_dir_snapshot` 也补了 gone 检测（兜底）
- **两个坑**：① watcher 抢先软删后，前端再调 `syncDirSnapshot` 会返回 false 而不刷新——**事件本身就是"磁盘变了"的信号，不能拿返回值二次判断**；② 删除后必须清 `_listCache`，否则 `loadImages` 吐出旧列表

### 2.6 其他功能改动

- 新建文件夹合并成一个，**建在右键的那个文件夹里面**（旧版有"子文件夹/同级"两个，容易建错）
- 新增自动置顶：新图拖进某文件夹 → 该文件夹提到同级第一位（只写 `picnest_dir_order`，不改名）
- 恢复顶栏 `01` 隐藏编号按钮 + `renameTarget` 保留前缀（否则改个名就把排序编号弄丢）
- 导出加「导出（去掉数字前缀）」（副本去前缀，原库不动）
- 诊断日志默认关闭（`PICNEST_DIAG=1` 才开）

## 3. 当前架构决策（别随手推翻）

1. **直链索引**：库里不存图片副本，只记路径 + 元数据。
2. **取数走 HTTP**（独立端口），IPC 只留给写操作和事件。
3. **缩略图 key = `fnv1a(file_path)`**：**任何改名路径都必须迁移缓存**，否则灰卡。
4. **`sort_order = 0` 表示"未分配"→ 排最前**（新图置顶）。SQL：`(sort_order=0) DESC, sort_order ASC, id DESC`。
5. **非 manual 模式不允许拖动换位**（防止按临时画面重建 `sort_order` 覆盖手动排序）。
6. **文件名前缀只认 2–3 位数字 + 下划线**，4 位（`0524_`、`2023_`）一律不碰。
7. **`dir_rel` 是小写**，而 `picnest_dir_order` 的 key 用**磁盘真实大小写** rel。两者混用会静默失效（`findNode` 已做大小写回退）。

## 4. 已知问题 / 待办

### 4.1 高优先级

1. **三级缩略图缺失**：旧版有 400 / 1024 / 2048 三级，Rust 版只有 400。大格显示原图会重现旧版的"解码预算爆掉 → 裂图"。**这是与旧版效果差距最大的地方。**
2. **「标题」排序与手动排序的冲突提示**：`排序同步文件名` 开着时，「标题」项已无意义（就是手动排序的副本且不能拖）。建议置灰或加提示「改顺序请用手动排序」。
3. **目录删除的语义**：旧版把文件夹移到内部 `picnest-trash/<rootId>/<id>-<name>`（可还原文件夹），Rust 版直接进 Windows 系统回收站。要统一得补目录 + `trash_group` 维护。

## 5. 坑清单（血泪）

1. **`.wi` 是通类选择器**（`style.css`）：任何新元素加 `class="... wi"` 都会自动播 173ms 延迟 + 520ms 淡入。想要"立即出现"就别加。
2. **缩略图缓存 key 是路径哈希**：改名必迁移。置 NULL 是灾难。
3. **`dir_rel` 小写 vs 磁盘真实大小写**：查树要大小写回退（`findNode`），写 `dir_order` 要用真实大小写。
4. **删除后要清 `_listCache`**：LRU 会把旧列表吐回来。
5. **内部操作要设 `_suppressFsSyncUntil`**：否则 watcher 会把刚写的顺序盖回去。
6. **sync 命令在主线程**（`[main]`），重活必须 `spawn_blocking`。
7. **改名的 DB 写入要包事务**：6224 次独立提交是 6224 次 fsync。
8. **`--disable-gpu-vsync` / `--disable-frame-rate-limit` 别再加回来**：它们不是性能来源，反而让 renderer 无上限出帧。
9. **CDP 合成输入测不出真实手感**：必须用系统级 `SendInput`。
10. **最小化窗口会让消息泵看起来"不堵"**：测泵时保持窗口正常显示。
